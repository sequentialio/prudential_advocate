# Scope — Website additions and client intake app (proposed 2026-11-10)

Technical build scope for the follow-on engagement proposed to the firm on 2026-11-10. Commercial terms live outside this repo. Build only what the firm approves; this doc is the engineering checklist for each piece.

## Part one — website additions (this repo)

### `community.html` — Community Involvement
- Same page frame as `about.html` (`pagehead--photo` banner + dark scrim); licensed banner photo with a row in the root `image-credits.md` before it ships.
- Sections: intro · *Veterans on our team* (three team members; name, branch and photo **only with each person's written consent**) · *Pro bono and volunteer work* (attorney's volunteer work at a low-income tax clinic, named only with the clinic's permission) · room for other programs.
- Copy drafted from the firm's notes, reviewed by Robbie. Factual only; no comparative or "most generous" claims (Rule 7.1).
- Add to primary nav + footer nav on **every** page, `api/sitemap.js` static list, OG/meta, Spanish strings in `i18n-es.js` (coverage script must stay at zero), cache-busters bumped.

### `careers.html` — Careers + application form
- Content: why work here · openings (or standing "we welcome resumes" note) · what the firm looks for · veterans encouraged to apply · equal-opportunity statement · how to apply.
- **California hiring rules:** no salary-history question (Labor Code § 432.3), no criminal-history question (Fair Chance Act, Gov. Code § 12952), short applicant privacy note. Robbie reviews before launch.
- Form fields: first/last name, email, phone, position, message, resume. Honeypot + rate limit as in `api/contact.js`.
- **Resume upload safeguards** (`api/careers.js`, new):
  - Accept only `.pdf`, `.doc`, `.docx`; max 5 MB.
  - Verify by **magic bytes** (`%PDF-`, OLE `D0 CF 11 E0`, ZIP `PK\x03\x04` + `[Content_Types].xml`), never by extension or client MIME.
  - Store as `<uuid>.<ext>` in a **private** Supabase Storage bucket (`applications`), no public URL; served to staff only via short-lived signed URLs; `Content-Disposition: attachment`.
  - Never render, execute or inline the file anywhere on the site.
  - Email the firm via Resend with the resume attached (Resend attachment limit is fine at 5 MB), to the address(es) in `portal_settings` (reuse `inquiry_forward_email` or add `applications_forward_email`).
  - `applications` table (RLS: anon insert via the API only, authenticated read) + **Applications** tab in `portal.html`, mirroring the Messages tab, with a signed-URL download button.
- Fallback if the firm declines uploads: same form without the file field; copy tells candidates to email the resume.

### Two new team profiles
- `<slug>.html` from an existing profile; card in `team.html` grid (staff order per Kevin); `assets/team/<slug>.avif` 820×820 crop from the supplied headshot; info sheet via `scripts/sheets/build-sheets.mjs` (scrapes live pages, re-run after the pages deploy).

## Part two — client intake app

Digitizes the 17-page *Estate Planning and Asset Questionnaire* (8 sections, ~300 fields, 59 yes/no, 5 "provide a copy" items) as a guided mobile form.

### Architecture (decide at kickoff; recommendation first)
- **Separate repo + Vercel project** at `intake.prudentialadvocate.com` (one CNAME at NameSilo; never touch MX/TXT). Shares the existing Supabase project (`gsvdtgtkhnpqlwhbsfal`) so staff use the same `/portal` login.
- PWA: manifest + service worker; drafts persisted on-device (IndexedDB/localStorage) until submit; installable; offline draft editing.
- Stack per global default (Next.js App Router + TS + Tailwind v4 + shadcn, RHF + Zod) unless a static form is enough; WCAG 2.2 AA; brand = site palette (red `#E32525`, ink, ivory).

### Form behaviour (Essential tier)
- 12 steps mapped to sections I–VIII; conditional sections (single client → one column; no minor children → skip guardians; "same as alternate trustees" → skip executor/agent/attorney-in-fact lists); repeatable rows (children, prior spouses, gifts, accounts, properties, policies); computed totals; beneficiary percentages validated to 100 %.
- Review screen → Section VIII attestation (checkbox + typed name + date per preparer) → submit.
- Confidentiality notice on first screen (wording from Robbie).

### Output and staff side
- `intake_submissions` table (RLS: insert via API only; authenticated read/update), JSON answers + generated PDF in a private bucket.
- **PDF in the paper form's layout and numbering (I–VIII)** so review and filing do not change; generated server-side (same approach as `scripts/sheets/`).
- Email notification to `portal_settings` addresses (link to portal, PDF attached only if the firm asks).
- **Intake** tab in `portal.html`: list by client/date, open PDF, mark reviewed, download.

### Higher tiers (build only if chosen)
- **Plus:** Spanish (all tiers now include Spanish per final proposal) · save-and-resume across devices via emailed private link (token, 30-day expiry) · document attachments for the "provide a copy" items (same upload safeguards as careers) · portal-initiated invitations with status sent/started/submitted.
- **Complete:** up to two more firm forms on the same engine · reminder emails to unfinished drafts · one-page attorney summary.
- **App stores:** Capacitor wrapper, published under the firm's Apple/Google developer accounts; Apple guideline 4.2 risk noted — offline drafts + install are the justification.
